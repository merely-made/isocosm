## Constraints and ownership

- Cosmograph owns native identity, biological/process admission, matter and
  deterministic saved authority. Component stores begin there under D42;
  this experiment does not replace the live Population or its save format.
- Eidetic/Muniment supplies durable record mechanics and provenance;
  Chartulary's graph/facets are existing sparse metadata mechanisms. Their
  storage iteration is not a substitute for native identity ordering.
- Cosmograph-host owns coherent committed native/section reads and revisions.
  Product view dependencies must not weaken endpoint staleness/admission.
- Mesocosm's scene adapter owns visible-subject extraction, inspection and
  product presentation state. Isometer owns generic scene/render contracts.
  Rootstock/Genet owns document hosting, layout and GPU composition.
- Shared subject identity survives value/order changes. Removal and a new
  lifetime must not inherit stale routes. Source revision, image revision,
  body revision and child lifetime remain distinct.
- Libraries are reference material. A native component-scene comparison is
  a rebuildable projection over existing identifiers, never a second world.
- Native replay/conservation checks, CPU measurements, GPU submissions and
  physical frame/input observations retain their actual qualification scope.

## Phases

The comparison keeps three architectural options explicit:

| Option | Use in this experiment | Consequence |
| --- | --- | --- |
| Retained scene rows with precise publication dependencies | The baseline and default | Simple renderer handoff; unrelated section writes can reuse both body storage and the image. |
| Native identity-ordered component projection | Developer comparison backend | Reuses Cosmograph's identity and query contracts; capture and owned materialization have measurable costs. No authoritative Population migration is implied. |
| One ECS store and scheduler for scene and DOM | Reference option, not selected | Shared authoring does not justify replacing document layout, event routing or retained widget lifetimes. Those owners keep their contracts. |

The native component projection is deliberately a small query/storage test.
It cannot establish the performance of an archetype ECS, a full native record
migration, or direct renderer queries without materializing the current body
vector. Those would need their own implementation and comparison.

### C1. Narrow extraction dependencies

Replace the whole-world-section invalidation with the actual native and
product inputs required by the scene. Preserve physical pose, native
awareness, site/played changes and source replacement. An opaque unrelated
section write must keep scene data and projection identity. Current world
revision still accompanies command admission and observed publication.

- Done when: a genuine pre-fix control executes and fails; unrelated section
  writes reuse the scene; actual native/physical/view changes invalidate it;
  refused/no-op publication and coherent source reads preserve their meaning.

### C2. One committed subject, two presentations

Publish one immutable subject reading for the DOM inspector and the scene
annotation. Retain stable native and part identity while values change;
selection, order, mounting and source lifetimes have explicit behavior.
The producer's picture and its action context remain distinguishable.

- Done when: both presentations expose the same subject/read revision;
  value updates and reorder preserve identity; removal/replacement refuses
  stale actions; camera/UI-only work leaves native state and history alone.

### C3. Native component-store scene comparison

Build the smallest identity-ordered typed projection stores suggested by
D42 and the existing source shapes. Compare their canonical output with the
current retained scene. Keep scene hierarchy storage separate from DOM
behavior and native cohorts. The comparison must identify exactly which
component/query behavior is implemented; it is not a claim that E9 is done.

- Done when: row and component projections agree on real native fixtures,
  membership/order/value changes and source replacement; clone isolation
  and native identity are checked; no foreign identity allocator or saved
  duplicate state is introduced.

### C5. Didgeridoo bindings, conditional follow-on

The local Didgeridoo checkout retains the Piccolo crate identity. Its
stackless Lua, fuel and coroutine/Sequence seams are relevant existing
mechanisms, not an implemented reactive composition layer. Bind immutable
query results to a source/lifetime, route explicit intents through native
admission, and cancel subscriptions/event waits on teardown. UI scheduling
and simulation clocks remain separate. Formula/query ecological roles use

biology. Choose concrete fuel/memory/operation budgets with the binding.

- Done when: the earlier experiment justifies this phase; bindings have
  actual source and lifecycle controls, finite work bounds, deterministic
  native admission/replay controls and no hidden authority writes. This is
  recorded direction, not an implemented phase of the current prototype.

  opaque unrelated section changes action admission but neither body storage

- 2026-11-04: terrain residency depends on actual ground, realized window
  cells and materials, independently of body membership and picture accents.
  Camera and inspector updates retain those cells when they are unchanged.
- 2026-11-04: the component backend currently captures all columns and
  materializes a fresh owned body vector. Its measured cost is conversion
  work, not a packed/archetype-store, selective-query or incremental-update
  result. Keep retained rows as the default while those cases remain open.

  first live fixture reached a checkpoint before that command and had an
  empty presented roster. C4 now starts the dev clock paused before warmup

  from seed and population alone.
- 2026-11-04: full column capture plus owned body-vector materialization
  costs more than the owned-vector clone control. The matched host trials
  have the same native source, scene work and qualified upload totals. There
  is no measured reason to switch the default renderer handoff to columns.
- 2026-11-04: the dominant observed host wall-time span is the shared outer
  raster call around `RenderCore::try_rasterize_scaled_for`. Its inner
  renderer timing is smaller, so further attribution must separate work,

  that shared presentation boundary.
- 2026-11-04: C4 uses the real coarse native bench world, with native body
  documents and actual presented-part inspection, not a physical-placement

  native copy/replay have separate controls.
- 2026-11-04: the selected Genet already has `try_begin_native_frame`,
